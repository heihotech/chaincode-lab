Reading on-chain data without a paid node provider

Most tutorials assume you already have an Alchemy or Infura key wired up. But for side projects, quick scripts, or situations where you simply don't want to hand over an email address, there are solid ways to query Ethereum and EVM-compatible chains without a paid — or even a registered — provider. Here's a practical rundown of what actually works in 2024.

Public RPC Endpoints

Every major EVM chain publishes at least one free, unauthenticated RPC endpoint. These are rate-limited and unsuitable for production traffic, but they're perfectly fine for one-off reads, local scripts, and learning projects.

  • Ethereum mainnet: https://cloudflare-eth.com or https://eth.llamarpc.com
  • Arbitrum One: https://arb1.arbitrum.io/rpc
  • Optimism: https://mainnet.optimism.io
  • Polygon: https://polygon-rpc.com
  • Base: https://mainnet.base.org

Chainlist (chainlist.org) aggregates these for hundreds of networks and even benchmarks latency in real time. Always cross-check a few endpoints; some community RPCs go stale without notice.

Making Raw Calls With curl

You don't need any library to prove this works. The Ethereum JSON-RPC spec is just HTTP POST with a JSON body. Here's how to fetch the latest block number on mainnet:

curl https://eth.llamarpc.com \
  -X POST \
  -H "Content-Type: application/json" \
  --data '{
    "jsonrpc": "2.0",
    "method": "eth_blockNumber",
    "params": [],
    "id": 1
  }'

You'll get back something like {"result":"0x13a4f2b",...}. Convert that hex to decimal and you have the current block. Reading a specific storage slot, checking an ERC-20 balance, or calling any view function follows the same pattern — you're just changing the method and params.

Using ethers.js or viem Without an API Key

Plugging a public RPC into your existing tooling takes one line. With ethers v6:

import { JsonRpcProvider } from "ethers";

const provider = new JsonRpcProvider("https://eth.llamarpc.com");

const block = await provider.getBlockNumber();
console.log("Current block:", block);

// Read an ERC-20 balance
const abi = ["function balanceOf(address) view returns (uint256)"];
const usdc = new Contract("0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48", abi, provider);
const balance = await usdc.balanceOf("0xYourAddressHere");
console.log("USDC balance:", balance.toString());

With viem, the pattern is similar — you create a publicClient pointing at your chosen transport URL instead of using the named chain presets that default to their own infrastructure.

Running a Local Node (More Practical Than You Think)

If you need reliable reads without rate limits, running a light client locally has gotten much easier. Two options worth knowing:

Helios

Helios is a trust-minimized Ethereum light client written in Rust. It syncs in seconds using consensus layer checkpoints and exposes a local JSON-RPC on 127.0.0.1:8545. You still need a beacon node URL (Cloudflare offers a free one), but you don't need a full archive node.

# Install via cargo
cargo install helios

# Run against mainnet
helios ethereum \
  --consensus-rpc https://www.lightclientdata.org \
  --execution-rpc https://eth.llamarpc.com \
  --rpc-port 8545

Once it's running, point any provider at http://localhost:8545 and you're reading chain state with cryptographic verification, not trust.

Geth in Light Mode

Geth's light sync mode downloads only block headers and fetches state proofs on demand. It's heavier than Helios but battle-tested:

geth --syncmode light --http --http.api eth,net,web3

Light mode requires connected full-node peers willing to serve proofs, which has historically been unreliable on mainnet. It's more dependable on testnets or if you control your own full node elsewhere.

Querying Indexed Data With The Graph

Raw RPC calls are great for current state, but historical queries ("show me all Transfer events for this token over the last 10,000 blocks") get expensive fast. The Graph lets you query pre-indexed subgraphs with GraphQL for free on its hosted service and decentralized network.

const query = `{
  transfers(first: 5, orderBy: timestamp, orderDirection: desc) {
    from
    to
    value
    timestamp
  }
}`;

const res = await fetch(
  "https://api.thegraph.com/subgraphs/name/uniswap/uniswap-v3",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ query }),
  }
);
const data = await res.json();

No API key needed for most public subgraphs. You're querying someone else's indexed data, so verify it against raw RPC for anything security-sensitive.

When Public RPCs Break

Public endpoints will occasionally rate-limit or go down. A few practical mitigations:

  • Rotate through a list of endpoints and retry on failure.
  • Cache results aggressively — block time is ~12 seconds, so you rarely need fresher data than that.
  • Use viem's fallback transport, which handles endpoint rotation automatically.
  • For scripts that run infrequently, a free tier on Alchemy or QuickNode (no credit card for the basic plan) is often the pragmatic call.

The point isn't to avoid node providers forever — it's to know you're not blocked without them. For prototyping, scripts, and read-only tooling, the public infrastructure is more than enough to get real work done.
