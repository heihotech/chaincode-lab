Connecting a React frontend to a contract with wagmi

Once your contract is deployed, the next step is wiring up a frontend that can actually talk to it. wagmi is the go-to library for this in the React ecosystem — it handles wallet connections, chain switching, and contract reads/writes with a clean hooks API. This guide walks you through a minimal but complete setup, from installing dependencies to reading state and sending transactions.

Project Setup

Start with a fresh Vite + React project, then install what you need:

npm create vite@latest my-dapp -- --template react
cd my-dapp
npm install wagmi viem @tanstack/react-query

wagmi v2 uses viem as its transport and encoding layer (replacing ethers.js), and it requires React Query for async state management. These aren't optional — they're core to how wagmi works internally.

Configuring wagmi

Create a wagmi.ts config file at the root of your src folder:

// src/wagmi.ts
import { createConfig, http } from 'wagmi'
import { mainnet, sepolia } from 'wagmi/chains'
import { injected, metaMask } from 'wagmi/connectors'

export const config = createConfig({
  chains: [mainnet, sepolia],
  connectors: [injected(), metaMask()],
  transports: {
    [mainnet.id]: http(),
    [sepolia.id]: http(),
  },
})

Then wrap your app in the required providers inside main.tsx:

// src/main.tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { WagmiProvider } from 'wagmi'
import { config } from './wagmi'
import App from './App'

const queryClient = new QueryClient()

ReactDOM.createRoot(document.getElementById('root')!).render(
  <WagmiProvider config={config}>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </WagmiProvider>
)

Connecting a Wallet

wagmi exposes useConnect, useDisconnect, and useAccount for wallet state. Here's a minimal connect button:

import { useAccount, useConnect, useDisconnect } from 'wagmi'

export function ConnectButton() {
  const { address, isConnected } = useAccount()
  const { connectors, connect } = useConnect()
  const { disconnect } = useDisconnect()

  if (isConnected) {
    return (
      <div>
        <p>Connected: {address}</p>
        <button onClick={() => disconnect()}>Disconnect</button>
      </div>
    )
  }

  return (
    <div>
      {connectors.map((connector) => (
        <button key={connector.id} onClick={() => connect({ connector })}>
          Connect with {connector.name}
        </button>
      ))}
    </div>
  )
}

The connectors array reflects whatever you passed into createConfig, so the UI adapts automatically when you add more wallet options later.

Reading Contract State

Assume you have a simple counter contract deployed on Sepolia:

// Counter.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public count;

    function increment() external {
        count++;
    }
}

Use useReadContract to fetch the current count:

import { useReadContract } from 'wagmi'

const CONTRACT_ADDRESS = '0xYourDeployedAddress'

const abi = [
  {
    name: 'count',
    type: 'function',
    stateMutability: 'view',
    inputs: [],
    outputs: [{ type: 'uint256' }],
  },
] as const

export function CounterDisplay() {
  const { data, isLoading, error } = useReadContract({
    address: CONTRACT_ADDRESS,
    abi,
    functionName: 'count',
  })

  if (isLoading) return <p>Loading...</p>
  if (error) return <p>Error: {error.message}</p>

  return <p>Current count: {data?.toString()}</p>
}

The as const assertion is important — it lets TypeScript infer the exact return type from the ABI, so data is typed as bigint rather than unknown.

Writing to the Contract

Sending a transaction uses useWriteContract. Pair it with useWaitForTransactionReceipt to track confirmation:

import { useWriteContract, useWaitForTransactionReceipt } from 'wagmi'

export function IncrementButton() {
  const { writeContract, data: txHash, isPending } = useWriteContract()

  const { isLoading: isConfirming, isSuccess } = useWaitForTransactionReceipt({
    hash: txHash,
  })

  function handleIncrement() {
    writeContract({
      address: CONTRACT_ADDRESS,
      abi,
      functionName: 'increment',
    })
  }

  return (
    <div>
      <button onClick={handleIncrement} disabled={isPending || isConfirming}>
        {isPending ? 'Awaiting wallet...' : isConfirming ? 'Confirming...' : 'Increment'}
      </button>
      {isSuccess && <p>Transaction confirmed!</p>}
    </div>
  )
}

A Few Practical Notes

  • ABI management: In a real project, export your ABI from a generated file (Hardhat or Foundry both support this) rather than hand-writing it inline.
  • Chain mismatch: Use useSwitchChain to prompt users to switch networks if they're on the wrong one before sending a transaction.
  • Invalidating reads after writes: wagmi's React Query integration means you can call queryClient.invalidateQueries after a confirmed transaction to refetch contract state automatically.
  • Error handling: viem throws typed errors (e.g., UserRejectedRequestError), so you can catch and display meaningful messages rather than raw strings.

Putting It Together

The full flow is: configure chains and connectors once in wagmi.ts, wrap your app in providers, then use purpose-built hooks wherever you need wallet info, contract reads, or writes. Each piece is isolated — your connect button doesn't need to know about your contract, and your contract components don't need to manage wallet state directly.

From here, you can layer in features like ENS resolution with useEnsName, watching contract events with useWatchContractEvent, or multi-call batching with useReadContracts. The hooks API stays consistent regardless of what you're doing, which makes wagmi genuinely pleasant to build with once you've got the initial wiring in place.
